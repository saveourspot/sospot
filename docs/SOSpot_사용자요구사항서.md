# SOSpot 사용자 요구사항서 (URS) v1.2

> 소상공인 상권 이상징후 탐지 서비스 · 2026년도 공공데이터 활용 공모전
> 작성일 2026-08-14 · 팀 SOSpot · 관련 문서: `SOSpot_요구사항정의서.md` (v0.4)
> v1.2 변경: 추적 매트릭스 정확화 — UR-19·20을 신설 FR에 직접 연결, 역방향 추적성 서술 보정

이 문서는 **사용자가 무엇을 할 수 있어야 하는가**를 기술한다. 화면과 시스템이 그것을 **어떻게** 제공하는가는 요구사항 정의서(FR)에 있으며, 두 문서는 9장 추적 매트릭스로 연결된다.

---

## 1. 사용자 및 이해관계자

| ID | 구분 | 역할 | 특성 |
|---|---|---|---|
| **U1** | Primary User | 정책 담당 주무관 | 데이터 분석 비전문가, 시간 압박, 근거 자료 필요 |
| **U2** | Secondary User | 소상공인지원센터 상담사 | 짧은 상담 세션 중 빠른 조회 필요 |
| **S1** | Demo Stakeholder | 공모전 심사위원 / 시연 관람자 | 처음 접함, 짧은 시간, 사전 지식 없음 |

**U1의 이용 목적**: 분기별 지원사업 **우선검토 후보 지역 선별**.
SOSpot은 최종 지원 대상을 결정하지 않는다. 담당자가 모든 지역을 동일하게 검토하는 대신 **먼저 살펴볼 후보를 좁히도록** 돕는 것이 서비스의 역할이다.

**S1을 명시하는 이유**: 이 서비스가 실제로 가장 먼저 만나는 상대는 심사위원이다. "설명 없이 짧은 시간 안에 이해되는가"는 부가 조건이 아니라 요구사항이므로 별도 이해관계자로 둔다. 다만 서비스의 실사용자는 아니므로 User가 아닌 Stakeholder로 구분한다.

> **페르소나 성격에 대한 고지**: 위 사용자 정의는 서비스 목적과 업무 환경으로부터 도출한 **가정 페르소나**다. 실사용자 인터뷰로 검증한 것이 아니며, 검증 시 수정될 수 있다.

## 2. 용어 정의

| 용어 | 정의 |
|---|---|
| **이상징후** | 특정 지역·업종의 점포 수 변화가 대전 전체 동일 업종 추세 대비 뚜렷하게 부진한 상태 |
| **이상징후 등급** | 지역의 이상징후 정도를 4단계로 구분한 것 — **정상 / 관심 / 주의 / 중점검토** |
| **상대격차** | 지역 증감률과 대전 전체 동일 업종 증감률의 차이 |
| **우선검토 후보** | 이상징후 등급이 높아 정책 검토를 먼저 권하는 행정동 |

> 문서·화면·API 전부 위 4개 등급명만 사용한다. '위험', '심각', '경계' 등 다른 표현은 쓰지 않는다.

## 4. 인수 기준

각 요구사항이 충족됐다고 판단할 수 있는 조건이다. **사용자가 무엇을 할 수 있게 되는가**로 기술하며, 구현 방식은 FR에서 정한다.

| UR | 인수 기준 |
|---|---|
| UR-01 | 지도 진입 후 추가 조작 없이 대전 82개 행정동 **전부**의 이상징후 등급을 식별할 수 있다 |
| UR-02 | 모든 이상 판정 결과에서 **지역 증감률과 대전 전체 증감률을 동시에** 확인할 수 있다 |
| UR-03 | 업종 대분류 단위로 범위를 좁히면 해당 업종 기준 결과로 즉시 전환된다 |
| UR-04 | 후보 지역이 이상징후 정도 순으로 정렬되어 제시된다 |
| UR-05 | 지역 상세에서 **점포 수 추이 · 지역 증감률 · 대전 증감률 · 상대격차** 4종을 모두 확인할 수 있다 |
| UR-06 | 해당 지역에서 이상징후가 두드러진 업종을 상위 순으로 각 수치와 함께 확인할 수 있다 |
| UR-07 | 지역 변화와 대전 전체 변화를 동일 기준·동일 척도에서 비교할 수 있다 |
| UR-08 | 표본이 기준에 미달하는 지역×업종 조합은 판정 결과와 **분리되어 제시되며 사유를 확인할 수 있다** |
| UR-09 | 큰 분류의 이상징후 결과에서 세부 업종 단위 결과로 이어서 이동할 수 있다 |
| UR-10 | 두 행정동의 핵심 지표를 동일 기준으로 나란히 비교할 수 있다 |
| UR-11 | 근거 수치를 포함한 결과를 파일로 반출할 수 있다 |
| UR-12 | 사전 정의 테스트 질의 30개 중 **27개 이상**에서 의도한 결과에 도달한다 |
| UR-13 | 모든 AI 답변에서 그 답변의 근거가 된 수치를 함께 확인할 수 있다 |
| UR-14 | AI 답변에 언급된 지역의 상세 정보로 추가 검색 없이 이동할 수 있다 |
| UR-15 | 업종만 지정해도 대전 전체의 시점별 추세를 확인할 수 있다 |
| UR-16 | 모든 화면에서 데이터 출처와 기준 분기를 확인할 수 있다 |
| UR-17 | 등급 산출 방식(계산식·판정 제외 기준)을 서비스 내에서 확인할 수 있다 |
| UR-18 | 등급 표기 지점에서 **대전 내 상대적 위치**라는 설명을 함께 확인할 수 있다 |
| UR-19 | 분석 지표에 '폐업률'을 사용하지 않고 '점포 수 변화'로 표기하며, **점포 수 감소가 폐업을 의미하지 않음을 안내한다** |
| UR-20 | 첫 진입부터 모든 기능이 인증 없이 동작한다 |
| UR-21 | 첫 화면에서 서비스 정의와 이번 분기 핵심 요약을 별도 이동 없이 파악할 수 있다 |
| UR-22 | 분석 조회는 즉시 응답 수준, AI 응답은 대기 상태가 인지되는 범위 안에서 반환된다 (구체 수치는 NFR-01/02) |
| UR-23 | 일반 업무용 데스크톱 해상도에서 지도와 상세 정보를 함께 확인할 수 있다 |

> **UR-08 관련**: 표본 하한의 구체값은 URS에서 정하지 않는다. 실데이터 분포 검증을 거쳐 요구사항 정의서 6.2에서 확정하며, 선택 근거를 함께 기록한다.

## 5. 사용자 시나리오

### 시나리오 A — 분기 검토 (U1, 주 시나리오)

> 대전시청 소상공인 담당 주무관이 다음 분기 지원사업의 검토 후보 지역을 좁혀야 한다.

1. SOSpot에 접속한다. 메인에 **기준 분기, 이상징후 등급별 지역 현황, 대전 체감경기 지표**가 함께 보인다. 점포 수는 늘었는데 체감경기는 나빠졌다는 대비가 눈에 들어온다. *(UR-21, UR-16)*
2. 이상징후 지도로 이동한다. 82개 행정동이 등급별로 구분되어 있고, **중구 목동**이 중점검토로 표시되어 있다. *(UR-01, UR-04)*
3. 목동을 선택한다. 음식업이 **123 → 121 → 117개**로 줄었고, 지역 증감률 −3.3%인 반면 대전 전체는 +3.0%로 **상대격차 −6.3%p**임이 제시된다. 감소폭 자체는 작지만 대전 전체가 성장하는 동안 혼자 줄었다는 점이 드러난다. *(UR-05, UR-02, UR-07)*
4. 이 지역의 다른 이상 업종도 함께 확인한다. 표본이 부족한 업종은 판정에서 분리되어 사유와 함께 표시된다. *(UR-06, UR-08)*
5. **대흥동**과 비교한다. 대흥동은 부동산업 상대격차가 −11.3%p로 더 크다. 두 지역의 검토 순서를 정한다. *(UR-10)*
6. 근거 수치를 포함해 결과를 반출한다. *(UR-11)*

> 시나리오에 등장하는 수치는 2026.06 기준 실데이터 계산 결과다. 메인 화면의 요약 수치는 화면 로직 확정 후 확정값을 표기한다.

### 시나리오 B — 자연어 진입 (U1)

1. 질의창에 **"최근 음식업이 계속 줄어든 지역 알려줘"** 라고 입력한다. *(UR-12)*
2. 조건에 해당하는 행정동 목록이 **근거 수치와 함께** 반환된다. *(UR-13)*
3. 목록에서 목동을 선택해 상세로 이동한다. *(UR-14)*
4. 이어서 **"목동이 왜 중점검토야?"** 라고 묻는다. 지도에서 본 것과 **동일한 수치**로 답이 온다. *(UR-13, UR-05)*

> 4단계가 이 서비스의 신뢰성 증명 지점이다. AI와 대시보드가 같은 분석 로직을 공유하므로 두 경로의 수치가 어긋날 수 없다.

### 시나리오 C — 상담 중 조회 (U2)

1. 상담 중 **"대전 교육서비스업 요즘 어때?"** 를 질의한다. *(UR-15)*
2. 대전 전체 교육업 추이와 특히 부진한 행정동이 반환된다.
3. 해당 지역 상세로 이동해 상담 자료로 활용한다. *(UR-07)*

## 6. 제공하지 않는 것

사용자가 기대할 수 있으나 **의도적으로 제공하지 않는** 항목이다. 화면에 명시해 오해를 막는다.

| 항목 | 미제공 사유 |
|---|---|
| 개별 점포의 폐업 여부·예측 | 상가업소번호 유지율이 분기별로 96.8% → 89.6%로 불안정해 개별 추적을 신뢰할 수 없다 |
| 실시간·월 단위 갱신 | 원천 데이터가 분기 단위다 |
| 매출·유동인구 분석 | 해당 공공데이터를 활용하지 않는다 |
| 미래 시점 예측 | 3개 분기로는 예측 모델의 신뢰 구간을 확보할 수 없다. 과거 변화 탐지에 집중한다 |
| 대전 외 지역 | 범위 밖. 구조는 확장 가능하게 설계한다 |
| 지역×업종 교차 경기지수 | BSI는 지역과 업종이 각각 별도 축이라 "대전 음식점업 BSI"가 존재하지 않는다 |
| **검토 목록 저장 / 계정 기능** | 일정상 제외 확정. 결과 반출(UR-11)로 대체한다 |

> 검토 목록은 세션 임시 저장 형태로도 제공하지 않는다. 절충안을 두면 화면·상태 관리가 늘어나 17일 일정에서 위험하고, 후보 선별이라는 가치는 순위 목록과 결과 반출로 이미 전달된다.
