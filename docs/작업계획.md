## 0. 협업 규칙

> 상위 규칙: `개발조율안.md` §15(Git), §16(작업 상태), §21(변경 통제)

### 작업 흐름 (매 세션)

1. `git pull --rebase origin main`
2. **§3 태스크 리스트**에서 다음 할 것 선택
3. `feat/<task-id>-<short-desc>` 형태로 브랜치 생성 (예: `feat/p3-07-leaflet`)
   - **브랜치 존재 = 진행 중 신호**. 별도 상태 관리 불필요
4. 작업 → 커밋(들) → push
5. PR 생성 → 상대 리뷰 → main merge
6. **막힌 경우**: PR을 draft로 두거나 브랜치명에 `-blocked` suffix + PR 코멘트로 사유 기록

### Git 규칙

- **main 직접 커밋 금지**. 모든 기능은 feature branch → PR → merge
- 브랜치 명명: `feat/<task-id>-<slug>` / `fix/<task-id>-<slug>` / `chore/<slug>` / `docs/<slug>`
- 커밋 컨벤션: `feat:` / `fix:` / `chore:` / `docs:` — 제목에 태스크 ID 포함 권장 (예: `feat(pipeline): P1-02 load.py 작성`)
- 진행 중인 브랜치 확인(Windows PowerShell): `git branch -a --sort=-committerdate | Select-Object -First 10`

### 이 문서(`작업계획.md`) 갱신 규칙

- **작업 상태 반영을 위해 이 문서를 수정하지 않는다** (진행 상태는 git branch로 추적. Codex 조율안 §16)
- 이 문서 수정은 **계획 자체가 변경될 때만**: 태스크 추가/삭제/순서 변경, 완료 기준 정정 등
- 개발조율안.md의 항목(§21 변경 통제 리스트: 산식·schema·API contract·조인키·문구 등)은 **단독 변경 금지**. 상대 팀원과 합의 후 개발조율안 수정 → 작업계획 반영

### 문서 참조

- **산식·규약**: `개발조율안.md` §2~§14
- **검증 기준값**: `개발조율안.md` §18 (편의상 이 문서 §1.5에도 요약)
- **각 AI의 로컬 컨텍스트**: Claude Code는 `CLAUDE.md`, Codex는 자체 설정 — 상대 AI의 인스트럭션 파일에 의존하지 말 것

### P2-01. `metrics.py` — 기본 지표 계산

- **선행**: P1-08
- **산출물**: `pipeline/src/metrics.py` (일부)
- **작업**: `fact_store_count` 조회 후 pandas로 조합 단위 지표 계산
  - 분석 가능한 기준 분기 `t`를 동적으로 결정하고 시간상 연속된 `t-2`, `t-1`, `t`가 모두 존재하는지 검증
  - `fact_dong_score`에 이미 완료된 기준 분기는 재계산하거나 덮어쓰지 않고, 신규 분석 가능 분기만 처리
  - `g(d,c,t) = (N_t − N_{t−1}) / N_{t−1}` (지역 증감률)
  - `G(c,t) = (ΣN_대전(c,t) − ΣN_대전(c,t−1)) / ΣN_대전(c,t−1)` (대전 전체 동일업종)
  - `RD = g − G` (상대격차)
  - `CUM = (N_t − N_{t−2}) / N_{t−2}` (누적 변화율)
  - `C = 1 if g(t) < 0 and g(t−1) < 0 else 0` (연속감소)
  - `sample_size_flag`: `N_{t−2} < 20` → 'LOW', else 'OK'
- **완료 기준**: 202606 기준 MAJOR 대상 조합 604건이 `sample_size_flag='OK'`
- **커밋 메시지**: `feat(pipeline): P2-01 조합 단위 기본 지표 계산`
